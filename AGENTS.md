## Data Directory Root (user instructions, 2026-10-21)

- `AppPaths.Find()` walks up from the executable's folder and treats the first ancestor containing `static\index.html` as the root; `data\` (messages.db, files, config.json with the pairing token) lives under that root. The real user data is in `D:\Archives\20260919 Link Flow\data`.
- Never copy `static\` into a packaged or daily folder such as `dist\LinkFlow-<version>-local`. A copy makes that folder its own root and silently starts an empty `data\` with a new pairing token, so the desktop and the paired phone appear to have lost all messages and files. This happened on 2026-10-20 with `LinkFlow-0.4.0-local`; the original data was intact and was restored on 2026-10-21 by renaming that folder's `static` to `static.off`.
- Cause (from the session history; no project script copies `static\`): the run folder was made by hand with `Copy-Item LinkFlow-0.4.0-publish LinkFlow-0.4.0-local -Recurse` (the `-publish` package intentionally contains `static\` for the portable ZIP), and later `cp -r static/. dist/LinkFlow-0.4.0-local/static/` and `Copy-Item static/* ... -Recurse -Force` were run to "sync" it. `build.ps1` and `LinkFlow.csproj` (which excludes `static/**`) are not involved. `build.ps1` also stops the app, rewrites the desktop shortcut and restarts it, so do not use it for daily updates.
- Update the daily run folder only with `scripts\Update-LocalDaily.ps1` (`-CheckOnly` to preview, `-StopRunning` to exit a running instance with its own `--stop`, `-Start` to restart and verify). It publishes with `dotnet publish -r win-x64 --self-contained` into `dist\LinkFlow-<version>-local`, refuses to run if that folder already holds `static\` or `data\` (report it, do not delete), and with `-Start` checks that `data\runtime.json` in the project root shows the new PID and that the message count did not drop. It does not touch the desktop shortcut or Run entries; check them separately. Do not copy `-publish` folders or `static\` into `-local` by hand.
- Packaged builds must resolve to this project's root: keep only the executable and its runtime files in `dist\LinkFlow-<version>-local`, with no `static` or `data` beside them. After any packaging or update, check `data\linkflow.log` and `data\runtime.json` in the project root for the new start entry and PID, and compare the message count before and after.
- Do not delete or merge a stray `data\` folder created by a wrong root; report it and let the user decide.
